### Strengths

- Garage state is separated into per-VIN SQLite files and vector roots. Registry paths are stored relative to the data root, legacy absolute paths under that root remain readable, and resolved paths outside it are rejected.
- `VehicleContext` and nested record payloads are immutable, SQL operations qualify records by VIN, and every scoped record operation revalidates the captured profile/library/source context after `BEGIN IMMEDIATE` on the same Garage connection.
- Legacy `/query` and `/library` behavior now fails closed until a scoped index exists, source routes check approved source associations, and the unscoped manual-review blueprint is disabled by default.
- The provider endpoint gate is literal-address-only, rejects traversal and userinfo, disables environment proxies and redirects, and requires identity encoding. Model identity, embedding shape, image decoding, strict JSON parsing, full local JSON Schema validation, stream cleanup, and token-driven transport cancellation are materially stronger than the base revision.

### Issues

#### Critical (Must Fix)

1. **Conflicting request VINs can cross the active-Garage boundary — `cc_workshop/application/garage_routes.py:69` and `cc_workshop/application/garage_routes.py:79`.** The record routes build their context only from the path VIN and ignore the `X-Vehicle-VIN`/query/body identity used by the other private routes. A request carrying active Garage A in `X-Vehicle-VIN` can read a Garage B record by addressing `/api/garages/<VIN-B>/records/<B-id>`; the current code returns `200` with B's payload. This creates a confused-deputy path once the UI or middleware consistently supplies an active VIN and fails the requirement that private routes remain authorized against that active Garage. **Fix:** resolve one request context through `request_vehicle_context()`, normalize the path VIN, and require equality before opening the repository; return scoped `404` for a mismatch. Apply the same rule to create and read routes, and add tests for header A/path B for both reads and writes.

#### Important (Should Fix)

1. **Garage records accept and emit non-standard JSON — `cc_workshop/garage.py:370`.** `json.dumps` uses `allow_nan=True` by default. An HTTP payload containing `NaN` is accepted with `201`, persisted, and returned as `{"reading":NaN}`, which is not valid JSON and defeats the claimed JSON-safe record boundary. **Fix:** serialize with `allow_nan=False`, reject non-string mapping keys for non-HTTP callers, normalize serialization failures to `invalid_record`, and test `NaN`, positive/negative infinity, and non-JSON values.

2. **Capability-probe cancellation is swallowed — `cc_workshop/inference.py:443-447`.** `probe_capabilities()` catches every `ProviderError`, including `CANCELLED`, and converts it to an `unknown` capability. A pre-cancelled token therefore returns a normal report instead of raising `CANCELLED`; mid-probe cancellation aborts the transport but is hidden from the caller. This can make cancelled activation work appear completed. **Fix:** re-raise `CANCELLED` and `CLIENT_CLOSED` (and preserve external `asyncio.CancelledError`), while converting only probe failures that genuinely mean “unknown.” Add pre-dispatch and blocked-transport probe cancellation cases.

3. **The JSON-schema capability probe does not prove schema behavior — `cc_workshop/inference.py:468-480`.** The probe sends a schema request but accepts any ordinary text completion through `_completion_from_response`. A provider that ignores `response_format` and returns `ok` is cached as supporting `json_schema`. Local validation still protects the renderer, but capability detection is false and an enabled adapter can fail every structured request. **Fix:** use a sentinel schema with required/const or otherwise unmistakable constraints, strictly parse the probe text, validate it locally, and cache support only when the returned value proves the declared dialect.

4. **The configured “total” deadline and stream-count limit do not bound a whole operation — `cc_workshop/inference.py:617-619`, `cc_workshop/inference.py:703`, and `cc_workshop/inference.py:747-749`.** `total_timeout` is restarted for every send/read await rather than measured from operation start. In addition, `max_stream_events` increments only for text-bearing deltas, so an endpoint can send unlimited role-only or usage events. `[DONE]` merely sets a flag and parsing continues (`cc_workshop/inference.py:717-719`), allowing content after the terminal marker. A slow or non-text event stream can therefore run indefinitely while staying below every per-await and content bound. **Fix:** establish one monotonic deadline per public operation/session, pass remaining time to each await, count every parsed data event, make `[DONE]` terminal, reject post-terminal bytes/events and duplicate finish markers, and add slow-drip, role-only flood, and post-`[DONE]` tests.

5. **Malformed UTF-8 escapes provider error normalization — `cc_workshop/inference.py:564` and `cc_workshop/inference.py:894`.** Ordinary bodies are decoded before `_loads_provider_json` enters its normalization block, and SSE frames decode outside a normalization guard. A provider response containing invalid UTF-8 raises raw `UnicodeDecodeError` rather than safe `ProviderError(INVALID_RESPONSE)`. **Fix:** use strict incremental UTF-8 decoding inside the bounded parser and map decode failures to `INVALID_RESPONSE` with no raw-body-bearing cause; cover ordinary and byte-split SSE cases.

6. **Browser source navigation loses the confirmed VIN — `app.py:516` and `static/app.js:24`.** `request_vehicle_context()` permits `?vin=...`, but `/viewer` redirects to `/pdf/<manual>#page=...` without preserving that VIN, and generated citation URLs do not include it. Normal iframe/new-tab navigation cannot add `X-Vehicle-VIN`, so a valid authorized viewer request becomes `needs_identification` at `/pdf`. There is no successful source-viewer test. **Fix:** carry an explicit, validated VIN through the same-origin viewer/PDF URL or use a scoped server-side authorization token, and add a follow-redirect test that serves an approved source while still rejecting another Garage.

7. **Existing persisted inference profiles cannot be read after this commit — `cc_workshop/inference_settings.py:205-209`.** The base revision saved profiles without a `runtime_policy` object, while the new reader unconditionally evaluates `raw["runtime_policy"]` and splats it into `RuntimePolicy`. Upgrading an existing installation therefore raises `KeyError` on restart. **Fix:** accept the prior missing/string representation through an explicit migration path, validate it against the supplied current policy, rewrite the migrated profile atomically, and add a fixture produced by the base schema.

#### Minor (Nice to Have)

1. **Most newly added `ClientLimits` fields are not validated — `cc_workshop/inference.py:330-336`.** Negative values for `max_request_bytes`, `max_sse_event_bytes`, `max_stream_content_bytes`, and `max_stream_events` construct successfully and then cause every operation to fail with misleading size errors. **Fix:** validate every byte/count limit as a positive non-boolean integer and add constructor tests for zero, negative, boolean, and non-integer values.

### Assessment

**Ready to merge? No.** The core architecture is substantially improved and all existing tests pass, but the HTTP record routes still permit a conflicting active/path VIN to select another Garage, and CC-T009 cancellation, capability-probe, deadline/SSE, and decode semantics have reproducible contract gaps. The legacy inference-profile read regression also makes upgrades unsafe until migrated.
