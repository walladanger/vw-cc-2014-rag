## Confirmed baseline defect and isolated regression

Evidence:
- [app.py lines 357-358](https://github.com/walladanger/vw-cc-2014-rag/blob/646df53b3945e8444877480b3976ca3e8b46007b/app.py#L357) passes `profile=VEHICLE_PROFILE`.
- [app.py lines 116-119](https://github.com/walladanger/vw-cc-2014-rag/blob/646df53b3945e8444877480b3976ca3e8b46007b/app.py#L116) prefers Chroma when the existing Chroma directory is present.
- [ChromaLibrary.retrieve](https://github.com/walladanger/vw-cc-2014-rag/blob/646df53b3945e8444877480b3976ca3e8b46007b/retrieve.py#L510) does not accept `profile`.
- [ChromaLibrary._passes_filter](https://github.com/walladanger/vw-cc-2014-rag/blob/646df53b3945e8444877480b3976ca3e8b46007b/retrieve.py#L481) also does not inspect profile/applicability; simply adding a keyword without filtering is insufficient.

New external fixture: `work/reproduce_chroma_profile_signature.py`.
- Imports the retrieval module but does not instantiate Chroma, import the application, create an index, load models or make network calls.
- Confirms by Python AST that the real application supplies the profile keyword.
- Uses `inspect.signature(ChromaLibrary.retrieve).bind(...)` with the application's keyword set; argument binding fails before retrieval code can execute.
- The fixture is intentionally **red on this baseline**: one passing source-precondition assertion and one failing compatibility assertion, exit 1.
- It demonstrates the exact interface mismatch, not an end-to-end HTTP test or future isolation correctness. A later implementation should make the bind test green and add real Chroma retrieval/garage isolation integration tests.
- No baseline application code was patched to obtain these results.
